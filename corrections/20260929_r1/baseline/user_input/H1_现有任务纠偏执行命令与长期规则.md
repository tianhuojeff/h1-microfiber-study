## 1. 固定研究定位：对象不换，分析重心必须改

### 1.1 当前采用的定位

| 层次 | 固定表述 |
|---|---|
| 研究对象 | 洗衣微纤维及有明确对应关系的洗衣截留物，在被拦截之后的后处理技术 |
| 研究问题 | 截留物如何从过滤位置被清理、转移、排液／脱水、暂存，并通过固体排出或承载物取出而移离指定装置边界？ |
| 分析角度 | 技术维度 |
| 分析类型 | 专题专利技术比较分析 |
| 研究方法 | 定向样本筛选、具体版本原文核验、技术特征拆解、操作时序与路径比较 |
| 核心成果 | 可追溯的技术路线差异、结构配合关系、维护接口与研发验证问题 |
| 外推边界 | 对选定样本作比较，不宣称代表全行业，不据此认定技术空白或市场格局 |

建议报告题目：

**《洗衣微纤维截留物后处理技术的专利比较分析——聚焦清理、转移、排液与移出路径》**

包内官方模板使用“分析角度不限”与“等”进行列举。当前按开放式列举理解，采用专题专利技术比较路线；**这不是组委会已明确认可本作品的证明**。

- “没有选择侵权、稳定性、新创性或布局中的一个，所以一定跑题。”

### 1.3 不得擅自改成其他任务

本轮不改成宏观态势、侵权／自由实施意见、稳定性审查、新颖性或创造性法律结论、完整专利布局、产品性能验证、实验论文或环境减排核算。

## 3. 旧规则冲突的纠正方式

### 3.1 必须保留的规则

保留原件、真实日期、来源和版本；保留同族归并依据；不捏造实测、检索、引用、法律状态；不将定向样本外推为行业总体；不把说明书实施方式自动当成授权权利要求的必备限定；不把队友未回传的成果标成已完成。

### 3.2 必须替换或缩限的规则

| 旧规则或旧做法 | 新规则 |
|---|---|
| 样本已经冻结，所以不能纠正分类或资格 | 历史快照只读保存；当前分析允许并且必须进行有记录的纠错与版本升级 |
| 统计分母永远是 14 | 14 是历史基线。当前分母由样本资格、归并单位和分析范围决定，不预设增减 |
| 不做法律分析，所以不核法律状态 | 不做侵权、稳定性等法律意见，但核对参赛核心样本资格及其具体文本版本 |
| 未发现实测取出，所以不计文本移出路径 | 文本路径与实测效果分开判断；文本明确或由同一实施方式充分支持的路径可进入技术比较 |
| 说明书不是独立权利要求，所以其技术方案不能计入 | 说明书可以支持技术披露分析；必须标清来源角色，不能据此扩大权利要求保护范围 |
| 一个同族的任一成员披露，都能写到代表文本名下 | 每条特征绑定实际来源公开号；跨成员使用须显式注明，不转移权项编号与授权范围 |
| 只要收集盒可拆就代表已完成安全处置 | 分别核对承载关系、移出路径、结构条件与最终处置；不相互替代 |
| 因为没有处置实证，技术方案就未解决任何后处理问题 | 先识别已经公开的技术手段，再限定其未验证的效果或下游处置边界 |
| 只改 Word，不改生成源 | 先改数据、正文源和脚本，再生成 Word／PDF；避免下次构建恢复旧错误 |
| 只改主矩阵，团队包仍照旧使用 | 生成新的当前团队包并标明旧包已被替代，保持当前版本一致 |
| 必须等测量资格具备才能成稿 | `measurement_ready=false` 仅约束实验效果主张，不阻止有证据的专利技术分析 |

本次明确的任务指令在 H1 工作范围内替代冲突的旧计划、旧记忆和旧统计口径，不覆盖执行环境的更高层级规则，也不删除无关项目指令。

## 6. 重建技术定义：不要再把不同问题塞进同一列

### 6.1 主技术链并非每项都必须按同一路径经过

统一问题框架为：

**截留位置 → 清理／脱离 → 转移 → 排液或脱水 → 暂存 → 移出指定边界。**

这是用于提问的框架，不是强加给所有专利的必备串联系统。允许“直接在可取出的过滤袋内截留”“清理与转移共用同一动作”“先移到收集腔再排液”等路线。某一环节不需要独立设置时，标为不适用并解释，而不是判定其技术不完整。

### 6.2 技术字段及判断对象

| 字段 | 必须回答的问题 | 不得混淆 |
|---|---|---|
| 截留位置与承载物 | 纤维留在滤面、滤材内部、集污腔还是可拆容器中？ | 有进出水口不等于有明确截留位置 |
| 清理／脱离 | 怎样使已截留物离开原过滤位置？刮、冲、反冲、旋转、振动或人工操作？ | 压缩收集物不当然等于清理原滤面；阀切换不当然等于再生 |
| 转移 | 固体从哪里到哪里，由水流、机械力、气流、重力还是整体搬出实现？ | 液体流动或部件可拆本身不必然证明独立的固体转移 |
| 腔体排液 | 哪个腔体内的游离液体由什么接口、在何阶段排向哪里？ | 普通过滤出水与维护前排空不是同一功能 |
| 固体脱水 | 是否对收集物降低附着／夹带液体，采用何种结构？ | 公开压滤／离心路径不等于有实测含水率；脱水不等于完全干燥 |
| 暂存 | 固体停在哪里，容器／腔体是否与过滤区域分离？ | 在盒内堆积不等于密闭、无泄漏或长期储存已验证 |
| 移出 | 移出的是固体、含固体容器还是含固体过滤组件？越过哪个边界？ | 盖板可拆不等于收集物可移出；移出装置不等于最终安全处置 |
| 操作与驱动 | 每一阶段由谁操作、何种动力、何种状态触发？ | 单个动作自动不等于全链条自动 |
| 维护接口 | 开盖、解锁、抽出、旋拧、断开管路等哪些动作有文本依据？ | 不推测没有披露的工具数量、时间或用户成功率 |

### 6.3 必须显式标注装置边界

至少区分：过滤表面／过滤腔边界、过滤模块边界、整台设备边界、可由用户取走的收集单元，以及后续废物处置环节。

外置集渣腔可能只是位于过滤腔外，仍属于同一过滤模块或整机。必须据图文判断；不得看到“external”就写成“已经排出整机”。

液路也要标出入口、出口所属部件及终点。腔体流出、回流到主过滤器、进入第二级过滤、进入设备排水、进入后续收集设施，不能统一写成“排入环境”。

### 6.4 移出路径的统一纳入规则

下列三类分开记录，不强求只有“倒出散装固体”才算技术移出：

- **直接排出固体**：目标物经出口、推送机构等离开所定义的装置边界。
- **取出含目标物的容器**：过滤袋、集污盒、可拆收集腔等承载关系与取出方式有明确披露或充分的同一实施方式依据。
- **取出含目标物的过滤组件**：滤芯／过滤组件本身承载截留物，并公开相应拆出路径。与独立集渣容器分列，不因其不是单独集渣盒而一概排除。

以下仅能支持维护可达性或尚待判断：单独盖板可拆、与收集物没有明确关系的壳体可分离、仅表示能打开但目标物如何移出仍不清楚。

“充分的同一实施方式依据”必须写清两项以上证据如何连接，不能用常识想象补出操作链。明确区分“原文明示”和“同一实施方式组合支持”，并保留其判断理由。

### 6.5 目标物与场景要有分层

不要默认所有微塑料都是纤维，也不要默认所有绒毛都是塑料。至少区分：明确洗衣微纤维／微塑料、洗衣绒毛或滤渣但材质未明确、非洗衣场景的技术对照。

主分析可纳入与洗衣截留物后处理有直接关系的样本，但要如实标明对象。非洗衣类比不得未经说明混入主样本分母；题目、适用条件与证据对象保持一致。

## 7. 重建证据记录与唯一数据源

### 7.1 不再使用单轴“证据等级”代替判断

以下维度彼此独立记录：

1. **来源位置**：独立权利要求、从属权利要求、说明书实施方式、附图及说明、背景技术、摘要。
2. **叙述对象**：本发明方案、可选实施方式、背景中介绍的现有技术、其他文献。
3. **技术披露状态**：已定位、充分组合支持、未定位、存在冲突、不适用。
4. **读取状态**：完整复核、部分复核、尚未取得、抽取失败。
5. **性能状态**：文本主张、具有实际数据、具有可比验证、未核验。没有相应材料时不补填正向状态。
6. **文本法律角色**：公开申请文本、授权文本或其他程序文件；具体法律状态另查。

说明书可以充分支持技术披露，但不自动支持某项授权权利要求包含相同组合。专利文字中的效果宣称不自动等于有实验数据；有数据也不自动意味着跨样本可比。

### 7.2 每一条核心技术判断的最低字段

建立当前权威数据文件 `analysis_master.json`，包含样本、文本版本、特征记录和证据关联。字段名称可配合现有代码调整，但不得丢失下列信息。

| 字段 | 要求 |
|---|---|
| `sample_id` | 当前样本稳定编号，不随展示顺序改变 |
| `family_key`、`family_definition` | 归并键、采用的同族口径及证据；数据库 ID 不替代全部核验 |
| `publication_id` | 实际支持该判断的具体公开号，不能只填同族代表号 |
| `grant_publication_id` | 对应授权号；没有或未确认则为空并说明 |
| `sample_role` | `core`、`supplementary`、`pending` 或 `excluded`，并附纳排理由 |
| `embodiment_id` | 属于哪个实施方式、方法或有依据的特征组合 |
| `stage`、`technical_feature` | 对应环节与准确的技术特征描述 |
| `object`、`start`、`end` | 处理的物料／部件及起点、终点 |
| `boundary`、`operation_order` | 越过的边界和有证据的操作次序 |
| `support_status` | 明示、同一方案组合支持、未定位、冲突、不适用 |
| `review_status` | 完整／部分／未取得／抽取失败等读取状态 |
| `source_role`、`subject_role` | 权项或说明书位置，以及是否属于本发明而非背景 |
| `claim_dependency` | 从属链；不涉及权项则明确不适用 |
| `locator` | 权项号、说明书段落号或物理页／图号，必要时并列 HTML 定位 |
| `evidence_excerpt`、`interpretation` | 最小必要原文与中文释义分开记录，不伪造逐字引文 |
| `source_path`、`source_url`、`source_sha256` | 本地原件、公开入口、内容哈希 |
| `verified_at` | 实际核验日期及时区，不用旧目录日期代替 |
| `old_value`、`new_value`、`change_reason` | 对纠错字段保留修订关系 |

网页行号依赖文件版本，引用时绑定哈希；不能把某次 HTML 行号当作稳定公开段落号。外文机译有歧义时核对原文，保持原词和释义可回查。

### 7.3 未知值与负向判断

- 尚未读到、抽取为空或网页打不开：记为**待核／读取不完整**，不是“未披露”。
- 在明确复核范围内没有定位到：写“在已复核的该版本文本范围内未定位”，不是“本领域不存在”。
- 原文相互矛盾：保留冲突，不为图表整洁强行填一个值。
- 某功能对该路线无须独立设置：标不适用，不等于欠缺。
- 不用“未知”“非实证”“未入权项”等关键词自动转为 0。

### 7.4 同族、实施方式与统计单位

保留“公开文本—申请／授权文本—同族—实施方式”映射。不同国别、A／B 版本的权项可能不同，分别读取。

同族层级可以统计“该同族经核验的某一文本披露了某功能”，但须标清采用的文本范围。若统计“当前核心授权文本的披露”，必须只用相应授权版本及其适用范围。

同一件文献中的互斥实施方式、互不依赖的从属分支，以及同族不同版本的特征，不能拼成一套从未公开的完整装置。为同一专利绘制不同路线时，使用实施方式子记录；统计时不得把它们重复当作多个同族。

## 8. 核验有效状态，但不把项目变成法律意见

### 8.1 核验任务

逐个拟作为核心对象的样本记录：法域、申请号、公开号、授权公告号、优先权／申请／公开／授权日期、法律状态核验日、关键程序事件、来源及相关文本版本。

在实际执行时检索相应官方登记、公告或可回查的原始程序记录；聚合平台用于导航与交叉核对，不只凭页面顶部的状态单词作最终判断。说明核验的时点，分清“截至研究截止日的状态”与“实际访问日看到的状态”。

不得凭编号后缀就推断当前有效；不得把某个 WO 国际公开文本直接当成所有国家都有效的授权专利；不得把某一同族成员的状态赋给全部成员。

### 8.2 样本分层

- **核心样本 `core`**：本轮按较严格参赛工作口径，已核实存在与研究有关的授权成员，且截至明确核验时点未发现使其不符合“有效、未失效”要求的状态，并明确核心所用的具体文本与法域。
- **辅助对照 `supplementary`**：用于解释技术路径或历史公开的其他文本，单独标明其角色和状态，不冒称有效授权样本。
- **待核样本 `pending`**：状态、文本、纳入关系或有效授权成员尚未核实，不计入“已核有效核心专利数”。
- **排除样本 `excluded`**：不符合场景、证据或核心纳入要求，保留排除记录，不从历史库无痕删除。

这种分层是项目采取的严格处理办法，不冒充组委会对每一类辅助材料的正式解释。若对比赛能否使用某类辅助对象仍有歧义，主分析以符合要求的核心对象为主，辅助材料清楚分开，记录资格解释风险；不得保证其必然获认可。

### 8.3 样本不足或状态受阻的处理

先检查现有同族是否有可核验的授权成员，再考虑有限的替换或补充检索。不得为了凑足 14 个而把未授权、已失效或状态不明对象写成有效。

如果部分样本尚不能确认，继续完成这些文献的技术整理与其他核心样本分析，但最终文件保留“资格核验待完成”的草稿状态。必要调整样本数量须记录旧数、新数和逐项原因。

核验样本资格并不等于已经完成稳定性、新颖性、创造性、侵权或自由实施分析。报告不得跨越到这些未经完成的结论。

## 9. 补齐真实、有限、与现有任务有关的检索过程

### 9.1 允许的补充目的

补充检索只为：核准已选专利及授权成员、补缺失原文或权项、验证争议技术分类、补真实检索过程、在核心对象不合格时进行必要替换。

不为了数量继续囤论文或专利，不为了做行业态势而无边界重建全领域母集。现有论文优先复用，只有直接影响背景事实或技术解释且现有资料不足时才定向补证。

### 9.2 最小检索设计

将“场景／对象词”与不同后处理功能分支结合。以下是检索意图，不是已执行的数据库语法：

| 分支 | 检索目的 | 关键词方向 |
|---|---|---|
| 场景与对象 | 查洗衣或洗衣废水中相关截留物 | laundry、washing machine、microfiber、microfibre、microplastic、lint、洗衣、微纤维、绒毛等；按场景与材质分层 |
| 清理与转移 | 查截留后的移除及输送机制 | cleaning、regeneration、backwash、scraper、transfer、collection、清理、反冲、刮除、转移等 |
| 排液与脱水 | 查液体分离和维护排空 | drainage、dewatering、compression、centrifugal、排液、脱水、压缩等 |
| 收集与取出 | 查承载物和最终维护接口 | removable、collection chamber、bag、cartridge、discharge、可拆、收集盒、排出等 |
| 精确核准 | 核对授权版本、同族、争议原句 | 已有公开号／申请号／授权号及特征短语 |

不用“清理 AND 转移 AND 排液 AND 移出”作为唯一入口，避免把只覆盖部分环节的相关技术排除。分类号必须在实际数据库核对体系、含义和字段，不将模板示例或其他平台语法直接照搬。

### 9.3 每次真实执行必须留下的记录

保存 `run_id`、数据库、访问时间及时区、检索字段、实际输入表达式、过滤条件、界面显示命中数、真实保存条数、结果来源、原始文件、截图、导出是否完整、错误或限制、与旧样本的关系。

原始检索结果保持只读，清洗后数据另存。截图应呈现检索式／字段、结果页面或筛选过程；原始内部截图与必要的匿名展示裁剪分开保存，不重绘网页、不合成命中数、不改写时间。

旧“98”只保留为历史日志中未完整保存的一次即时计数。可以在局限中简要说明，不必在各章反复强调。新执行检索以真实新日期保存，明确为补充核验；新结果不能倒推证明旧 98 条当时的组成。

网站受阻时换一个合法可用来源继续核验；仍无法取得则如实记录，不反复无效重试，不绕过权限，不以第三方摘要替代完整技术证据。

### 9.4 停止补充检索的条件

本轮必须的疑点已有原始证据或明确阻碍记录，核心样本资格与技术路线能够说明，补充过程已有可审查记录，即进入分析成稿。未解决的问题单列，不以追求绝对查全无限扩充任务，也不宣称绝对查全。

## 10. 技术比较正文的重写命令

### 10.1 先做逐件卡，再做路线比较

对全部当前纳入对象建立逐件技术卡，每张卡应能独立回答：

- 该件试图解决什么后处理问题，问题来自本发明文本还是背景描述？
- 关键结构与连接关系是什么，哪些有权利要求依据，哪些见于说明书？
- 截留物、输送液和排出液分别怎样移动？
- 清理、转移、排液、开盖／抽出按何顺序发生？是否在不同构型进行？
- 用户取出的是固体、容器还是过滤组件，移出什么边界？
- 有哪些结构条件、适用前提或仍待验证的性能？

卡片开头说明文本版本、样本角色与状态核验日；不能把全部细节压成“可拆，但未实证”一句话。

### 10.2 可优先验证的路线线索

以下仅是用于组织原文回查的候选路线，不得直接作为本轮已经核实的最终分类：

| 候选路线 | 优先回查的现有文献 | 必须核对的问题 |
|---|---|---|
| 机械清理并转入可取出的收集袋 | CN115637570A 及核实后的相应授权文本 | 刮除与转移是否共用机构；袋体承载关系与开门取袋路径 |
| 先排液／降低含水量，再转至外置集渣位置 | WO2022084677A1 及相关核心成员 | 排液、状态切换、固体转移与滑出部件是否属于同一可成立方案 |
| 通过二次流带液转移，再过滤或回流 | WO2023047385A1 及相关核心成员 | 液体与颗粒分别去哪；收集腔出口、循环与外排边界 |

若核验后需要拆分、合并或删除候选路线，以证据为准，不为了凑齐表格强行保留。

### 10.3 跨专利比较必须有技术含量

比较至少覆盖以下实际相关维度：

| 维度 | 应形成的分析 |
|---|---|
| 清理与转移的耦合 | 同一机构是否完成两个环节，还是需要分别驱动／切换 |
| 固液分离的时点 | 先排液再转移、带液转移后二次分离、压缩时分水，有何结构安排差异 |
| 固体与液体的终点 | 收集物与液体是否分开处理，循环是否会回到原系统 |
| 暂存与取出的界面 | 直接排固、取袋、取盒、取滤芯分别要求怎样的边界和连接 |
| 操作负担 | 文本可确认的开盖、解锁、抽出、断管等动作，不虚构时间和便利性评分 |
| 控制与状态切换 | 过滤／清理／排空／移出是否在不同构型，相关密封和开闭件怎样配合 |
| 文本与权项组织 | 独立项、从属链、说明书实施方式分别披露哪些关键关系 |

不得只有“方案 A 有刮板，方案 B 有反冲，方案 C 有滤盒”。每个核心比较段落写清**技术差别是什么、由哪些具体文本支持、对结构或操作提出什么条件、哪些效果尚未验证**。

尽量使每个跨样本结论有两个以上相应技术对象作为比较；只有单件依据的，明确它是个案观察而非共同趋势。

### 10.4 允许的推论和禁止的夸大

允许：“该方案把排液安排在滤渣转移前，因此比较时需要关注排液与开闭机构的配合；实际滴漏控制仍需验证。”

禁止：“该方案一定不滴水、成本最低、清理效率最高、最适合家庭、实现零排放。”除非有与具体条件一致的独立证据和比较基础，否则不能作此类性能排名。

“没有发现该组合”只能触发后续针对性检索，不能直接写成技术空白或拟申请方案具有新颖性／创造性。

## 11. 重算统计与重做图表

### 11.1 统计前置条件

先确定字段定义、读取状态、具体文本范围、样本层级与分母，再计算数量。禁止从现有中文描述中简单搜索“有／无／未知”来自动决定技术是否存在。

建议输出“正向披露、组合支持、未定位、待核／冲突、不适用”的分布，并写清合并口径。若图中只展示有明确依据的数量，未核对象仍须在附表显示，不能悄悄当作否。

### 11.2 分母规则

每张统计表和图写明：统计单位、纳入集合、文本范围、截止或核验日期、多标签／互斥性质。

主分析若以有效核心同族为单位，则 `N` 为符合该定义的核心同族数；辅助文本、同族另一公开版本和论文不重复加入。若另做全部技术对照样本表，单独标清其 `N_all`，不能与核心有效样本比例混用。

同族功能计数可取“至少一个已核相关文本披露”的逻辑，但必须列出实际支撑成员及样本范围。该计数不证明一个同族中的所有功能都组合在同一装置里。

当 `N > 0` 时，披露频次可写为 `K / N`；`N = 0` 时标不适用，不输出伪造的 0%。未知不是行业不存在，多标签之和不要求等于 100%。

### 11.3 本轮图表最低成果

1. **核心技术特征比较矩阵**：行是明确的样本／实施方式，列是后处理阶段与关键动作；使用短语而不是单纯颜色格。
2. **典型路线的固液路径与操作顺序示意**：至少覆盖经核验的几种主要差异；说明是依据文本绘制的分析示意，保留原件来源。
3. **一张有明确定义的样本内分布图**：可按移出方式、固液分离时点或技术标签统计，不必强行保留旧图 1。

流程图中固体路径、液体路径、构型切换与用户动作应可区分；不画原文没有的阀门、管道或物料终点。必要时对不同实施方式分图，不拼出“理想完整方案”。

不画基于定向小样本的行业年度趋势、地域份额、申请人实力排行或所谓布局空白图。已有共同申请网络可保留作培训历史附件；不能因为已经做过就强行放在正文占篇幅。

### 11.4 撤销旧指标的当前效力

## 12. 报告结构与写作要求

保持官方六部分结构，不用内部审计文档取代参赛正文。

### 一、报告名称

使用第 1 节的真实定位，不挂“布局”“侵权”“稳定性”“新创性”标签，不在标题里承诺未证明的环保效果。

### 二、选题背景

解释为什么“拦截之后的处理”是值得比较的技术问题，给出边界、场景、对象和目标。过滤效率、微纤维危害与背景论文只写必要内容，不能吞没主题。不得预设“现有专利普遍只过滤、不处理收集物”。

### 三、检索过程

写实际来源、时间和地域范围、检索词／分类、真实执行步骤、筛选与同族归并规则、核心与辅助样本构成、状态核验和截图。历史发现与本次补充核验分开，不补造一条从未发生的完整检索链。

### 四、分析过程及内容

建议按“样本与技术定义—清理与转移—排液与脱水—暂存与移出—跨路线综合比较”组织，放入逐件技术证据、比较矩阵和路径图。

技术比较应成为最大篇幅。以正文实质内容约一半或以上用于技术分析作为项目写作目标；这不是官方硬性比例。不能用免责声明、哈希和日志填充主分析。

### 五、结论建议

不少于 400 字。至少形成几条可回指原文的技术发现，例如操作顺序、固液分离位置、不同移出对象、结构配合与维护接口的差异。根据实际证据组织，不预填“谁最好”。

建议分清已知技术事实、基于结构的有条件推论、待验证问题。首段不得再把“本报告首先关于证据组织方法”作为主要成果，末段不得把样本未知泛化为行业缺失。

### 六、应用价值与亮点评述

不少于 300 字。说明矩阵和路线比较如何帮助研发明确模块边界、维护步骤、固液分离安排及试验问题。方法亮点可在“统一环节与装置边界”“把同一功能的不同操作顺序拆开”等方面据实表述；不说是全球首创方法，也不把严谨留档包装成专利创新性结论。

### 全文共同写法

每个核心专利事实靠近相应公开号与定位引用；不能只在文末堆一列链接。来源在不同法域或不同 A／B 文本之间切换时，显式说明。技术事实、推论和验证要求分开写。

局限集中说明：样本定向性、检索覆盖、状态核验范围、文本方案不等于已测性能。不要每个段落重复“不是法律结论、不是实证、不是行业代表”。

### 13.1 现有脚本的已观察风险

包内 `contest_report_20260928/build_h1_contest_report.py` 的旧版存在：

- 固定读取旧日期正文、矩阵和旧图文件；

### 13.3 文档质检
