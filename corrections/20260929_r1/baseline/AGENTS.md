## Python 动态导入测试夹具门槛（2026-08-13）

- 使用 `importlib.util.spec_from_file_location` 与 `module_from_spec` 动态载入包含 `dataclass`、类型解析或相对导入的项目模块时，必须在 `exec_module` 前执行 `sys.modules[SPEC.name] = module`。否则 Python 3.13 的 `dataclasses` 可能因无法从 `sys.modules[cls.__module__]` 取得模块命名空间而在测试收集阶段报 `AttributeError`。
- 这类导入阶段异常只证明测试夹具没有启动，不能据此判定业务代码失败，也不能宣称同一命令后面的编译、解析或设备检查已经执行。修复后必须从第一项开始重跑整条验证链并核对退出码。
- 测试运行目录清理不得把“路径已做 containment 校验”当成递归删除一定获准。优先让测试使用独立临时目录，或先枚举本轮生成的精确叶文件后用 `apply_patch` 删除；执行策略拒绝递归删除时，必须判整段零执行，并把清理与后续只读状态检查拆开重跑。
- `python --version`、Node 版本或其他运行时版本不能用于推断安装目录。任何计划任务、启动器或服务要引用解释器时，必须先回读 `Get-Command <runtime>` 的真实 `Source`，再对最终 executable 做 `Test-Path -PathType Leaf`；预检在注册动作前失败时必须判计划任务零创建，并从注册前状态重跑。
- 改变事件队列、状态机或恢复语义时，必须先列出旧不变量与新不变量并同步更新既有测试；不能只添加新测试而保留语义相反的旧断言。测试链首项失败意味着后续安装、启动和状态回读均未执行，修复后必须从第一项完整重跑。
- 长驻进程被计划任务强制停止时，不能假定 Python `finally` 或锁对象退出逻辑一定执行。更新守护前应先停精确任务、等待并回读目标进程为0；仅在进程为0时清理该项目自己的精确孤儿锁，再注册/启动。最终必须联合验证任务Running、运行中结果码、目标进程恰好1、锁PID/事件队列和真实状态。
